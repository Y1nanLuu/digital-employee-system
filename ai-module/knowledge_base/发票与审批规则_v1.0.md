## 条款

### INV-001 发票基本要求
报销发票须为增值税发票（纸质或电子），发票抬头必须为公司全称"北京中兴协力科技有限公司"且税号正确。电子发票须通过税务平台验真，验真记录由数字员工自动留存。抬头为个人或其它公司名称的发票不予报销。

### INV-002 审批阈值与路由
数字员工生成初审意见后，按单据总金额自动路由审批人：
- 单笔 ≤ 1000 元：部门主管审批；
- 1000 元 < 单笔 ≤ 5000 元：部门总监审批；
- 单笔 > 5000 元：分管副总审批。
金额以报销单申报总额（含税）为准。数字员工完成初审后流转至对应审批人，系统进入"等待审批"（awaiting_approval）状态。

### INV-003 数字员工初审规则
数字员工按以下顺序执行初审，任一环节不通过即给出对应结论：
1. 字段完整性：提交人、部门、费用类型、金额、费用日期、发票号、发票抬头、事由缺失任一项 → 退回补件（missing_info）；
2. 发票合规：抬头与公司全称不符 → 拒绝（rejected），引用 INV-001；
3. 制度依据：按费用类型检索制度库条款，判断金额/标准是否超限（如住宿超 TRV-003 上限、招待超 DAY-004 人均标准）→ 超限且无事前审批记录 → 转人工（needs_review）；
4. 以上均通过 → 建议通过（approved），并引用所依据的全部条款编号。

### INV-004 拒绝与退回的定义
拒绝（rejected）：单据违反制度强制性条款（如发票抬头不符、超时限、未事前申请的招待费），不再进入审批流；退回补件（missing_info）：单据信息不全，员工补充后可重新提交；转人工（needs_review）：制度无法自动判定或存在例外情况，由审批人人工裁决。

### INV-005 制度版本与追溯
所有制度文档按"文档编号-版本"管理（如 POL-TRV v1.0）。数字员工生成的初审意见必须引用作出判断所依据的条款编号与制度版本，审批人可凭条款编号回溯条款原文。制度更新后，历史初审意见仍引用其作出时的版本，不作追溯修改。
