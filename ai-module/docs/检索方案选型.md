## 0. 结论（TL;DR）

**主路径：条款级切片 + BM25（jieba 分词）**；降级：关键词包含匹配；向量检索不作为主路径，列为 **对比实验**（embedding 模型 bge-small-zh-v1.5 已在本机 HF 缓存，离线可用）。

## 1. 约束条件（决定选型的前提）

1.  本机 HF 缓存已具备离线推理条件：Qwen1.5-0.5B-Chat（生成，llm_server 已跑通）与 bge-small-zh-v1.5（中文 embedding）。向量方案**从"无法落地"变为"可行但不必要"**——主路径仍选 BM25，依据是下面 #2/#3 与对比表中的可解释性，而不再是"没有模型"；
2. 制度库规模小（3 篇文档 / 16 条条款），且会按版本增长——检索粒度必须是**条款级**而非文档级，否则"给出依据"只能给到整篇文档，不可追溯；
3. 制度文本术语固定（"住宿费""发票抬头""人均"），同义改写少——BM25 的词面匹配恰好是强项；
4. 单机 Docker Compose 部署（任务书要求）→ 方案必须零外部服务依赖。

## 2. 候选方案对比

| 方案                             | 命中质量                         | 可解释性                                 | 依赖                                               | 结论                                                                   |
| -------------------------------- | -------------------------------- | ---------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| **A. 条款级 BM25 + jieba** | 术语固定场景下足够（条款级打分） | 高：分数来自词频，引用直接给条款 ID+原文 | `jieba`+`rank_bm25` 两个纯 Python 包，单机可用 | **采用（主路径）**                                               |
| B. 关键词包含匹配                | 最低（无排序，多词命中歧义）     | 最高                                     | 零依赖                                             | 采用为**降级路径**（BM25 索引异常时）                            |
| C. 向量检索                      | 理论最好（同义改写鲁棒）         | 低（相似度不可解释，答辩时难以说明依据来源）       | bge-small-zh-v1.5 已在本机缓存，离线可行           | **D3 对比实验**（非主路径：16 条条款语料下收益不抵可解释性损失） |
| D. 混合（BM25+向量加权）         | 好                               | 中                                       | C 的超集                                           | 随 C 一并列对比实验                                                    |

## 3. 实施草图（D2 建、D3 评；**以下均为待实现的设计，非现状**）

- **切片单元**：条款。每条 = `{doc_id, doc_version, clause_id, text}`，如 `{POL-TRV, v1.0, TRV-003, 住宿费按城市分档……}`——条款 ID 在起草制度样例时已预埋（这是唯一已落地的一项），检索结果将天然可追溯；
- **索引构建（D2）**：解析 `knowledge_base/*.md` 的 `### CLAUSE-XXX` 标题 + 正文 → jieba 分词 → BM25 索引；文档版本取自文档头表格，实现 INV-005 的"意见引用条款版本"要求；
- **查询构造（D2）**：初审时按 `expense_type + 金额特征 + 关键词` 组合检索（如"差旅 + 住宿 + 一线城市"），返回 top-3 条款；
- **返回结构（D2）**：`{clause_id, doc_id, version, text, score}`，初审意见直接引用 `clause_id + version`。

## 4. 评测计划（对齐任务书"测试记录版本化"）

- D3 前构建 ≥10 个检索查询（覆盖 5 种费用类型 + 超限/合规两类问法），人工标注每个查询应命中的条款 ID；
- 指标：**依据命中率**（top-3 是否含标注条款）、引用正确性；
- **D3 对比实验**：同一查询集上跑 BM25（主路径）与向量检索（bge-small-zh-v1.5），报告两者命中率与失败案例差异，作为"为什么选 BM25"的实证支撑而非口头理由；
- 失败分类：分词断裂 / 条款表述歧义 / 查询构造缺陷，录入评测表随代码版本化。

## 5. 答辩口径（D3 对比实验后按实际数据回填结论，当前仅为草稿）

> 届时口径："主路径 BM25 不依赖任何模型也能给出带条款 ID 的可追溯依据——这是它的降级韧性；16 条条款的语料规模下词面匹配即够用且完全可解释。向量方案（bge-small-zh）我们有能力做，并用同一查询集做了对比实验，实验数据（见评测表）显示【D3 按实际结果回填】；在命中率差距不足以抵消可解释性损失的前提下，BM25 为主、向量为备。"——同时回答"依据怎么来的"与"为什么不用向量"两问。

> 注意：若 D3 实验显示向量命中率显著更高，则诚实回填并升级方案（语料增长后向量本就更适合），答辩讲"数据驱动的选型修订"比仅坚守既有结论更有说服力。
