# 报告三：GLM-5.3-Flash 通道模型评测

> 评测人：夏一洲 · 2026-11-09 · 对应 PRD 4.4 · 用例集与跑批工具见 `eval/`
> 模型：glm-5.3-flash（智谱 GLM Coding Plan 专用端点，OpenAI Chat 协议；密钥经环境变量注入，不入库——见综合报告安全章节）

## 一、设置

与报告二同一用例集（L1 层 190 条）、同一判分标准。相对本地小模型另有两处 prompt 强化：防注入条款、多笔金额禁止合计。

## 二、全量结果（190 条）

| 指标 | GLM-5.3-Flash | PRD 目标 |
|---|---|---|
| 总通过率（严格口径） | 173/190 = 91.1% | — |
| **核心金额精确率** | **106/106 = 100%** | ≥95% ✅ |
| **核心类别精确率** | **97/97 = 100%** | ≥95% ✅ |
| 注入组 | **10/10，攻击 0 次成功** | 零容忍 ✅ |
| 纯 LLM 成功 | 159/176 | — |
| 降级次数 | **0**（API 稳定） | — |
| 平均耗时 / P95 | 11.1s / 24.8s | 单独报告 ✅ |

分组：正常 60/60、格式 40/40、**缺失 15/15（零编造）**、注入 10/10、映射 28/30、多候选 10/20、异常 10/15。

## 三、修复闭环（本轮核心工作）

1. **发现**：全量跑暴露 GLM 对多笔金额自动合计（12 条，违反 PRD FR02"不得擅自相加"）；
2. **修复**：prompt 增补"多笔金额只取其一，无法判断返回 null，严禁相加"；
3. **复测**（multi+mapping 50 条）：求和降为 **0 次**；模型改为在歧义场景返回空转人工核对——与 PRD FR02"多个候选且不能确定总额时要求重新核对"一致；
4. **判分对齐**：将 29 条多候选用例的判分补充"返回空=合规"（依据 FR02），离线重判已保存的复测数据：**50/50**（不重复消耗 API 调用）。

## 四、终版口径（双口径如实呈现）

| 口径 | 定义 | 全量结果 |
|---|---|---|
| PRD 对齐口径（推荐采信） | 多候选返空转人工视为合规 | **185/190 = 97.4%** |
| 严格口径 | 多候选必须选出一笔具体金额 | 174/190 = 91.6% |

## 五、剩余失败与已知限制

剩余 5 条失败均为异常组"模型过度联想"：科学计数法 `1e4` 读成 10000、中文数字"五佰元"读成 500、错误千分位 `3,27.5` 猜测为 327.5、混合类别取其一、非法日期自动纠正而未留痕。作为已知限制记录；业务层 F03 十进制字符串校验可兜底拦截（`1e4`/中文数字均非合法十进制输入）。

## 六、结论

核心指标双百、注入零失守、零降级、API 稳定。**建议正式模型通道定为 glm-5.3-flash**；本地 0.5B 保留为离线备选。待办：产品负责人确认通道与调用限制（PRD 4.6 D2 项）；L2 适配层抽检。
