# V0.5 数据与档案设计

业务数据库支持SQLite及PostgreSQL，当前本机实际使用SQLite。原票以服务端生成的UUID存储键保存至受控文件目录，数据库存元数据和摘要；不存浏览器临时路径。

| 业务表 | 内容 |
| --- | --- |
| tasks | 归属员工、请求标识、确认字段、制度版本、状态、当前修订、初审及工具/审批/流转JSON日志、退回草稿 |
| parse_snapshots | 上传识别和任务解析快照，保留原值与置信提示 |
| invoice_files | 原名、MIME、大小、所有人、存储键、SHA256 |
| upload_batches | 本人多文件批次，各项草稿、提交和跳过状态 |
| policy_versions | 不可变版本内容及摘要；任务引用版本 |
| task_revisions | 原任务每次提交的确认字段、前后变化及阶段结果；修订号和重提标识唯一 |
| invoice_claims | 处理中票号及原件占用约束；拒绝释放，原任务重提排除自身 |
| file_access | 文件读取人员、时间和关联任务 |

财务服务另有receipts、invoice_registry、reimbursed_invoices、reimbursed_files四表，负责最终凭证、模拟查验台账及已报销票号/原件登记。预算只返回固定模拟余额，不扣减。

检索、工具、审批及事件目前按任务JSON和修订快照保存；本轮没有把它们虚构成独立物理表。指标从真实任务聚合，无须metric_snapshot表。

迁移只增加列和表，保留历史记录；旧demo-v1业务保留兼容读取，需退回重提时进入新流程。文件不可覆盖，换票保存新file_id并保留旧修订引用；校验摘要防篡改。文件写入使用临时文件、落盘和原子替换，数据库记录关联最终文件。

同请求重放、重提、审批和最终写回分别有状态与唯一约束。跨服务写回通过task_id幂等和恢复命令协调。数据库和文件须联合备份，操作见DEPLOYMENT.md；本机SQLite备份恢复已验证，PostgreSQL部署恢复仍待支持容器的环境实测。


最新增量：tasks增加唯一business_no字段，task_number_counters按员工编号及上海日期分配流水号；迁移按历史创建顺序回填，重放和原单重提保持原号。接收前在内存校验发票，拒收不写数据库/磁盘。cancelled记录员工撤销并释放invoice_claims，原票和历史保留。当前业务物理表由8张增加为9张。

最新补充：发起报销不展示历史申请或历史批次选择，仅恢复当前会话未完成草稿。历史统一在我的报销。状态筛选仅已通过、待审批、驳回待修改三类（可查看全部）。上传归档前及队列创建前查重，重复时提示原业务编号；已通过禁止重报，可撤销原申请先撤销再上传。同批重复项排除。invoice_files.invoice_fields完整保存原票号码、日期、购销方、总额和明细，原始识别与任务确认值分别留存。新增AC61及对应待测用例，最终组合测试按用户要求留待集中执行。
