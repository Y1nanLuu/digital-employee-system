## 任务要求与完成情况

任务要求为：按接口约定实现报销提交和任务查询，搭建模拟财务 API 骨架；提交后生成唯一任务编号并保存数据库，支持按编号查询，模拟预算查询接口能够返回样例结果。

| 验收项 | 实现位置与行为 | 验证结果 |
|---|---|---|
| 报销提交 | `POST /api/tasks`接收并校验项目、类别、金额、日期、说明及确认标记 | 正常请求返回201；非法请求不创建任务 |
| 唯一任务编号 | 使用UUID v4，作为`tasks.id`主键 | 同样内容使用两个新提交标识时，得到不同编号 |
| 数据库持久化 | 保存申请内容、状态、结果、制度依据、工具日志和审批记录 | 业务服务重启后按原编号查回完整记录 |
| 按编号查询 | `GET /api/tasks/{id}`，按角色控制可见范围 | 正常查询返回原记录；不存在或不可见返回404；未登录返回401 |
| 重复提交 | 同一员工、同一提交标识与相同内容返回原任务；内容不一致返回409 | 数据库重新连接及业务进程重启后仍有效，不增加任务和工具调用 |
| 模拟预算接口 | `GET /budgets/{project_id}`，Bearer密钥认证 | P001返回10000.00元，P002返回500.00元，币种CNY，标记为模拟数据 |
| 模拟审核写回 | `POST /results`，按任务编号保存并去重 | 财务进程重启后，相同结果返回原凭证；不同结果返回409 |
| 工具异常可追踪 | 校验财务响应的字段、金额与请求关联信息 | 异常响应产生可按编号查询的`failed`任务及失败日志 |

## 开发记录

### 1. 阅读基线与准备环境

检查仓库的`README.md`、`docs/API.md`、`docs/ARCHITECTURE.md`和相关后端代码。开发前工作区干净，当前分支为`zhoubo/backend-finance`。

基线已经提供FastAPI业务服务、SQLAlchemy任务模型、UUID编号、角色权限、规则状态流转和独立财务服务。本次沿用这些已有实现，完善契约、异常处理和验收覆盖。

在项目内创建`.venv`，按`backend/requirements.txt`安装锁定依赖。本次环境为Linux、Python 3.13.13、FastAPI 0.162.0、SQLAlchemy 2.1.8、Pydantic 2.14.2和pytest 9.2.0。依赖检查通过，未更改项目依赖版本。

### 2. 用回归测试复现问题

补充验收测试后，先在基线代码上运行相关用例，复现两个问题：

1. 8个空格构成的`Idempotency-Key`被接受并创建任务，缺少非空白校验。
2. 财务预算接口返回HTTP 200和数组时，业务代码直接按字典读取，产生`TypeError`，无法正常提交带有失败状态的任务响应。

进一步检查发现：预算缺少字段、金额非法、项目不一致，以及审核凭证内容与请求不一致等情况，也没有在工具调用边界统一校验。

### 3. 完善业务与财务接口

- 增加`TaskResponse`，为提交、列表、详情和审批接口提供统一的响应结构及状态枚举，运行后的`/docs`可查看完整契约。
- 提交标识增加非空白约束，保留已有的长度限制和重复提交语义。
- 新建`finance/schemas.py`，定义预算响应、审核写回输入和凭证响应；财务服务与业务调用端共用这些模型。
- 预算金额必须非负、有限且最多两位小数，币种必须为CNY，并携带模拟标记。
- 财务写回校验UUID任务编号、审核决定及非空原因；使用JSON模式序列化UUID后入库。
- 工具调用端核对项目编号，以及写回凭证的任务编号、决定和原因。结构错误或关联错误进入`failed`，保存失败日志；写回失败仍保留已作出的审核决定。
- 保留原有数据库结构、API字段名称、同步执行方式和审批流程，继续使用已有主键与唯一约束。

### 4. 扩充真实HTTP与重启验证

扩展`scripts/smoke.py`，使用独立临时数据库和随机本机端口启动两个服务，执行预算查询、报销提交、唯一编号检查和按编号查询，再停止并重启业务与财务进程。

重启后再次查询原任务，使用原提交标识重复提交，并向财务服务重复写入原审核结果，核验任务及凭证持久化和去重行为；随后验证审批续跑、预算不足拒绝、预算不扣减及指标统计。

首次真实HTTP验证时，服务已经正常启动，但健康检查超时。排查确认终端设置了代理且本机地址未绕过代理。脚本现使用不经过代理的本机HTTP客户端；修复后验证通过。

### 5. 整理说明与报告

更新`docs/API.md`，补充任务响应字段、提交标识要求、预算和凭证样例、错误码及财务响应校验规则。更新`README.md`，提供Linux / macOS环境安装、服务启动和验证命令，并链接本报告。

## 手动演示方法

1. 按README中的Linux / macOS或Windows步骤分别启动财务和业务服务。
2. 打开`http://127.0.0.1:8000/docs`，用演示员工账号`employee`登录，默认演示密码为`demo123`。
3. 调用`POST /api/tasks`，填写新的`Idempotency-Key`，提交P001项目交通费300元并确认字段。复制响应中的`id`。
4. 调用`GET /api/tasks/{id}`，填入该编号，检查申请内容、结果和工具日志。
5. 停止并重新启动两个服务，再按原编号查询；使用相同提交标识和内容重试，核对仍为原编号。
6. 打开`http://127.0.0.1:8001/docs`，展开预算查询操作，在`authorization`请求头中填写`Bearer local-finance-key`，分别查询P001和P002预算。
