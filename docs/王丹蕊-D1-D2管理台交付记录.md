# 王丹蕊 D1/D2 管理台模块交付记录

日期：2026-11-06。范围：D1-04、D2-04。基于 feature/wangke-employee-portal 原有实现直接修改，未推送远端。

## D1 页面与字段设计

沿用员工端侧栏、顶部身份区、状态标签及详情布局，避免重复建设页面。
- 工作概览：管理/审批身份展示任务总数、技术执行完成率、转人工率、平均系统耗时；增加指标口径及端到端耗时。
- 审批卡片：仅 approver 且 awaiting_approval 时出现；展示任务金额、说明、初审意见、条款来源及版本。意见不能为空，无检索条款时通过必须填写人工依据。
- 时间线：使用 events 的 at/status/message 展示实际状态变更。
- 工具日志：使用 logs 的 tool/method/at/duration_ms/success/request/response/error，分项展示，展开请求与响应。
- 审批记录：展示 actor/decision/comment/manual_basis/at，拒绝原因与人工依据可追溯。

## D2 接口对接

- GET /api/tasks：获取可见真实任务；支持前端状态与关键词筛选。
- GET /api/tasks/{id}：获取真实日志、时间线、条款及审批记录。
- GET /api/metrics：取服务端统计，不以本地任务列表代替全量指标。
- POST /api/tasks/{id}/approval：沿用 approve/reject/comment/manual_basis 契约；成功后刷新任务及指标。
- 空任务、空日志、空审批记录均明确展示空状态，不注入模拟记录。当前后端已提供上述接口，无需假数据补齐。

## 指标口径

完成率=(succeeded+rejected)/total；转人工率=manual=true/total；平均系统耗时为终态 succeeded/rejected 的耗时减人工等待；端到端耗时包含人工等待。分母为零由服务端返回 null，前端展示暂无数据。

## 手工验收步骤（待执行，不代表已通过）

1. 按 DEPLOYMENT.md 启动服务，用员工提交超阈值任务。
2. 以 approver/demo123 登录，选择任务，核对 awaiting_approval 及条款、预算。
3. 不填意见无法审批；缺少条款时，不填人工依据通过应提示错误。
4. 通过后刷新，检查后续写回、状态和审批记录；另建任务拒绝，检查原因与终止结果。
5. 展开真实日志，核对工具名称、请求响应、耗时及成功/失败状态。
6. 管理员登录核对指标与数据库；空数据库应显示暂无数据。
7. 断开后端时刷新，确认错误提示；恢复后刷新重试。
8. 以员工登录，确认没有审批操作入口。
