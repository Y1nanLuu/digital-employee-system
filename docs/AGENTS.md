# 开发日志保留规则

用户要求：之前的日志要保留，每天的都要保留。

- 已有开发日志必须保留，不得删除，也不得用新一天的报告覆盖。
- 每个有实际开发记录的日期单独保存日志；后续周勃的日志使用 `周勃-YYYY-MM-DD-开发日志.md` 命名。其他成员沿用各自命名方式，同样保留每日记录。
- 日志记录实际开发日期；任务编号（例如 D2）可以写入标题，但不能代替实际日期。不为没有记录的日期编造日志。
- 同一天的补充内容追加到当天日志，并注明补充时间。历史结论需要纠正时，追加更正说明及依据，保留原始记录。
- 现有文件保持原名，便于保留已有链接。新增日志时，在下表追加索引。
- 本规则针对开发日志；API、架构、部署等当前状态文档可随代码正常更新。
- 汇总文件按日期追加完整记录，不覆盖之前日期；新增或补充每日记录时同步更新汇总，保留每日原始文件。
