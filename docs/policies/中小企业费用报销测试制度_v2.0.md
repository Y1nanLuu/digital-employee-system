# 中小企业费用报销测试制度

版本：enterprise-demo-v2。生效日期：2026年11月11日。制定用途：课程项目开发、批量测试及演示。制度主体：示例科技有限公司。币种：人民币。参数由本组制定，参考依据见《公开制度研究与设计依据》。本制度不代表提供样本发票的学校、商家或任何真实企业的现行制度。

## 一 适用范围和共同要求

| 条款 | 规则 | 系统动作 |
| --- | --- | --- |
| GEN-01 | 员工因公司业务实际发生的费用方可申报，说明应交代业务用途，归属部门和项目 | 缺少说明或项目时提交前提示；业务用途存疑转人工 |
| GEN-02 | 单笔申报大于0且不超过5000元，最多两位小数；票面总额独立保存，允许识别大于5000元的票据 | 非法申报422；999、1000、1000.01、5000、5000.01分别测试 |
| GEN-03 | 自动初审阈值1000元；高于阈值转人工。金额等于阈值不因金额触发人工 | 最终路由由规则执行，模型意见不能改变阈值 |
| GEN-04 | 正常费用在发生后30个自然日内申报，计算到上海时区提交日 | 第30天正常，第31天转人工并要求逾期说明；不直接删除申请 |
| GEN-05 | 费用日期和开票日期分别保存；未来费用日期或未来开票日期须修正 | 字段校验；票面日期缺失时转人工补充 |
| GEN-06 | 项目预算按申报金额校验，金额等于可用预算允许继续 | 超预算拒绝，自动与人工通过前均查询；不扣减或预占预算 |
| GEN-07 | 原件、识别快照、确认值、制度版本、工具结果、审批及修改历史须留存 | 可授权预览下载，摘要及数据库联合备份 |

## 二 票据与重复报销

| 条款 | 规则 | 系统动作 |
| --- | --- | --- |
| INV-01 | 申报关联本人上传的原PDF或图片；号码、日期、购买方、销售方、含税总额、票面项目可核对 | 上传先检查清晰度和发票特征，明显模糊、非发票、关键字段无法识别时拒收且不保存；合格票据的辅助字段可补填；关键字段缺失进入人工核对 |
| INV-02 | 数电票按20位号码识别；传统增值税票按代码及8位号码识别 | 格式检查单独输出，不把格式合格记作验真成功 |
| INV-03 | 购买方应匹配配置的企业抬头；供应商为销售方，员工不是购销方名称 | 抬头不符、缺失或需要更正转人工，由员工补充，审批人不能改原始材料 |
| INV-04 | 调用模拟财务查验，核对号码、开票日期和含税总额 | 测试台账匹配返回valid；台账确认无效返回invalid并拒绝；未知返回unknown并转人工。页面始终显示“模拟查验” |
| INV-05 | 同一张票据在已通过或处理中申请中出现，按号码/代码核对，原件摘要辅助查重 | 精确重复拒绝或阻止新增；同一任务原标识重放返回原任务；退回后的原任务重新提交排除自身 |
| INV-06 | 同员工、日期、金额相同但票号不同，可能是不同消费 | 仅作为疑似重复风险转人工，不仅凭金额相同作重复拒绝 |
| INV-07 | 本期一票一单，不支持拆分票额多次报销 | 申报金额大于票面总额拒绝；小于票面总额须填写差异说明并转人工；已成功报销的票据不能再次申报剩余部分 |
| INV-08 | 不接受作废、红冲或模拟台账明确无效票据作为有效报销凭据 | 拒绝并记录票据风险；负金额票据可归档，申报走后续冲销流程，首版不处理负报销 |

## 三 交通与住宿

| 条款 | 规则 | 资料和处理 |
| --- | --- | --- |
| TRV-01 | 火车优先二等座、硬座或硬卧，飞机经济舱；其他席位须专项说明 | 填写交通工具及席位；超标准转人工 |
| TRV-02 | 出租车、网约车须填写业务起终点或用途，私人绕行费用自理 | 缺路线材料转人工；无需将全部行程文字自动解析为事实 |
| TRV-03 | 住宿需出差审批编号、城市、入住及离店日期、晚数、住宿清单 | 入住晚数为离店减入住，离店须晚于入住；申报按实际金额及标准比较 |
| TRV-04 | A类北京、上海、广州、深圳；B类天津、重庆、杭州、南京、成都、武汉、西安、苏州；C类珠海、佛山、东莞、无锡、常州、扬州、洛阳、桂林、大理、嘉兴、绍兴 | 城市归档在本组参数中，其余城市或空城市转人工，后续由负责人发布扩充版本 |
| TRV-05 | 员工每晚A/B/C为500/400/300元；主管650/500/400元 | 职级取预置身份或受控配置，不接受员工在表单提高职级；住宿上限=每晚标准×晚数 |
| TRV-06 | 超住宿标准的申请须说明原因和例外审批材料 | 转人工；普通审批不得直接绕过超预算或票据无效等硬约束；需改金额时退回员工修改 |

## 四 招待和餐补

| 条款 | 规则 | 资料和处理 |
| --- | --- | --- |
| ENT-01 | 招待须有客户/单位、业务事由、参加人数、陪同人数及事前审批编号 | 缺材料转人工；避免上传不必要的个人敏感信息 |
| ENT-02 | 一般招待每人不超过200元，单次不超过2000元 | 同时检查两项；超标转人工并要求说明；所有招待申请均由人工审批 |
| ENT-03 | 礼品、礼金、烟酒等单列明细，涉及个人消费或敏感用途须专项核对 | 关键词只作为风险提示；具体违规结论需有材料和人工决定 |
| MEAL-01 | 出差餐补每日上限100元，天数按出差开始至结束含首尾日计算 | 须填出差审批和天数，提供出差证明说明；当前发票上传入口只接收合格发票，证明材料单独人工核对；始终人工审批 |
| MEAL-02 | 已由客户、会议或公司提供同一餐食时不得重复领取对应补助 | 早餐20元、午餐40元、晚餐40元扣除；明确填已供餐次数，实际可领上限不低于0 |

## 五 办公 通讯 培训及软件服务

| 条款 | 规则 | 资料和处理 |
| --- | --- | --- |
| OFF-01 | 办公用品附明细或收货说明；超过1000元附采购审批编号 | 缺材料转人工；满足其余条件且不超阈值可自动初审 |
| TEL-01 | 通讯费用与公司业务相关，单次申报上限100元，说明服务月份 | 按月人工核对，超额转人工；本期不自动跨月合计扣减 |
| EDU-01 | 培训、会议及报名费附活动名称、业务关联及审批编号 | 人工审批；票面“赛事报名费”保留原文，是否属于业务培训由员工声明并提供材料 |
| IT-01 | 软件订阅、云资源、API服务及技术服务附服务期间、采购审批或合同编号 | 人工审批；云服务和技术服务可建议此类，保存映射原因 |
| OTH-01 | 未覆盖的业务费用归“其他”，保留票面名称 | 原票正常识别，人工确认适用依据；类别及制度新增须负责人审核发布版本 |

## 六 初审和审批程序

1. 提交后建立任务；确认票据来源和业务字段，重新解析形成任务内快照；检索适用版本条款。
2. 调用模拟预算、发票查验和重复报销检查工具，各自记录输入、结果和耗时。
3. 执行确定性规则，再由LLM读取本申请、引用和工具结果，生成“通过/存疑/拒绝”、理由和引用编号。只接受本次检索到的引用，保留模型来源和原始结构化意见。
4. 已确认的预算不足、无效票据、精确重复、申报超过票额，按硬规则拒绝并登记。材料缺失、超标准、未知查验、模型异常或金额超过阈值进入待审批。
5. 自动通过须规则无阻塞、金额不超阈值且有效模型意见为通过；LLM建议不能覆盖硬规则。LLM拒绝或存疑且缺少确定性拒绝依据时交人工。
6. 审批人可通过、拒绝或退回补充。退回必须说明待补内容；员工在原任务修改并重新提交，生成新修订记录，重跑解析、检索及全部工具；审批人不编辑员工字段。
7. 通过前重查预算、票据和重复情况。拒绝登记拒绝结果；退回不写最终审核凭证。所有决定和修改保留操作者、时间和前后内容。

## 七 测试与版本

金额、限额等值、超0.01元、缺材料、超期、未知及无效票据分别构造样本。测试制度B将自动阈值调整到500元，用同一999元申请验证路由差异；测试后恢复默认。历史任务保存制度快照，后续发布不改写历史依据。原demo-v1作为历史兼容测试资料保留，不能通过客户端任意选择旧制度绕过新规则。

本制度覆盖测试场景，不包含真实付款、预算扣减、税前扣除计算、多企业隔离、多级组织审批和会计凭证法定归档认证。

人工审批最新口径：通过、退回补充或拒绝并终止，退回补充进入returned供员工修改重提或撤销；撤销保留历史。系统硬规则拒绝仍单独记为rejected。


2026年11月12日审批终态修订：approve核对工具后写回；return只退回补充，不写最终财务结果，员工可沿原编号修订；reject保留拒绝原因及审批记录，写回模拟财务服务，凭证确认后rejected终止。终态禁止原单重提、撤销和重复审批。拒绝写回失败进入failed并保留拒绝决定和pending_writeback，受控恢复重放原决定，不得改成通过。
