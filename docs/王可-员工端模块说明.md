# 王可——员工端模块说明与贡献记录

## 职责与交付

本人负责费用报销数字员工系统的员工端，包括工作概览、报销提交、任务列表、详情及结果展示。本次在团队 Vue 3 + TypeScript 前端中完成界面与交互升级，保留审批人和管理员功能，未修改后端业务规则。

## 页面与交互

- 工作概览：累计任务、待人工审批、处理中和已完成数量，最近五条任务及快捷入口。
- 发起报销：项目、类别、金额、日期、说明；字段提取建议；提交前核对确认。
- 我的任务：按编号、项目、类别或说明搜索，按七种后端状态筛选。
- 任务详情：费用信息、初审结论、制度编号/来源/版本、执行时间线、工具日志和审批记录。
- 稳定性：草稿自动恢复、字段级错误、提交按钮锁定、幂等键、接口错误保留表单、空状态与响应式布局。

## 接口与状态

页面复用 `frontend/src/api.ts`，使用 `/api/me`、`/api/parse`、`/api/tasks`、`/api/tasks/{id}/approval` 和 `/api/metrics`。创建字段严格对应 `ClaimInput`：`project_id`、`category`、`amount`、`expense_date`、`description`、`confirmed`。

状态与后端一致：`queued`、`running`、`awaiting_approval`、`writing_back`、`succeeded`、`rejected`、`failed`。前端只做中文映射，不在浏览器中复制预算或审批规则。

## 已知边界

当前后端契约不包含票据上传和申请人补充信息接口，因此员工端不伪造这两项功能。课程演示使用 HTTP Basic；真实部署前需要替换认证并启用 HTTPS。任务跨角色变化需手动点击刷新，后续可增加安全的轮询或服务端推送。

## 答辩讲解要点

员工端不仅负责输入，更要让用户理解数字员工为何给出结论、流程停在哪一步。实现上通过共享 API 适配层与 TypeScript 类型保持前后端一致；通过草稿、校验、提交锁和幂等键提高可靠性；通过条款来源、版本和时间线保证可解释、可追溯。页面没有把 AI 初审包装成最终审批，也没有把未接入的票据功能冒充为已完成。
