# 王可——员工端模块说明与贡献记录

## 职责与交付

本人负责费用报销数字员工系统的员工端，包括工作概览、报销提交、任务列表、任务详情及结果展示。模块基于 Vue 3 + TypeScript，对接真实 FastAPI 接口；前端只负责输入校验、交互反馈和结果呈现，不复制预算、制度或审批业务规则。

## 页面与交互

- 工作概览：展示累计任务、待人工审批、处理中和已完成数量，以及最近五条任务和快捷入口。
- 发起报销：填写项目、类别、金额、日期和 1—500 字说明；金额采用文本输入并严格拒绝科学计数法、负数、零值和超过 5000 元的输入。
- 智能字段核对：调用真实字段提取接口，建议值不会自动覆盖原字段；金额或类别冲突时要求申请人显式确认并填写依据。
- 可靠提交：提交按钮锁定并携带幂等键；网络结果未知时保存原请求与原幂等键，允许原样重试，也可在核对任务列表后明确发起新申请。
- 我的任务：支持关键词搜索、七种后端状态筛选、刷新、空列表和无匹配结果提示。
- 任务详情：按任务编号加载最新数据，展示初审意见、制度编号/来源/版本、预算查询、写回凭证、执行时间线、工具日志、审批记录、字段补正和审计轨迹。
- 权限反馈：员工账号只读查看待审批任务；审批控件仅向审批角色开放，详情加载期间禁止重复操作。
- 稳定性：按账号保存表单草稿和结果未知的待确认请求；解析请求可取消；接口异常保留输入并给出中文错误；布局兼容窄屏。

## 接口与状态

页面复用 `frontend/src/api.ts`，使用 `/api/me`、`/api/parse`、`/api/tasks`、`/api/tasks/{id}`、`/api/tasks/{id}/approval` 和 `/api/metrics`。创建字段对应后端 `ClaimInput`：`project_id`、`category`、`amount`、`expense_date`、`description`、`confirmed`，字段冲突时附带 `parse_id`、`conflict_acknowledged` 和 `confirmation_note`。

状态与后端保持一致：`queued`、`running`、`awaiting_approval`、`writing_back`、`succeeded`、`rejected`、`failed`。前端只做中文映射，不在浏览器中自行判断预算是否足够或报销是否应通过。

| WK-13 | 后端返回 401、403、404、409、422 或 5xx | 显示可理解错误，保留用户输入 |

| WK-15 | 详情加载中连续点击 | 禁止重复选择和审批，避免旧详情覆盖新状态 |

## 已知边界

当前后端契约不包含票据上传和申请人补充信息接口，因此员工端不伪造这两项功能。课程演示使用 HTTP Basic；真实部署前应替换认证并启用 HTTPS。跨角色状态变化由用户主动刷新获取，后续可在不影响一致性的前提下增加轮询或服务端推送。

## 答辩讲解要点

员工端不仅负责录入，还要让申请人理解数字员工为什么给出结论、流程停在哪一步。实现上通过共享 API 适配层和 TypeScript 类型保持前后端一致；通过严格校验、草稿、提交锁、幂等键及未知结果重试保证可靠性；通过制度来源、解析快照、确认记录、字段补正、时间线和审计日志保证可解释、可追溯。页面没有把 AI 初审包装成最终审批，也没有把尚未接入的票据或补充信息能力冒充为已完成。
